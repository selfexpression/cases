# Пациенты и напоминания

В списке пациентов есть переключатель «Активные / Архив». Оба списка относятся к выбранной клинике; поиск работает внутри выбранного списка, в том числе по названию аппарата.

Когда лечение завершено, откройте карточку и нажмите «Завершить лечение и перенести в архив». Карта, визиты, заметки и история профгигиены сохраняются. Архивные пациенты не участвуют в напоминаниях. Кнопка «Вернуть в активные» восстанавливает обычный статус и расчёт напоминаний.

В форме пациента укажите аппарат свободным текстом: например, брекеты, пластинка, элайнеры или несколько аппаратов. Дата установки брекетов необязательна; будущая дата не допускается. Карточка показывает количество полных календарных месяцев от установки до сегодняшнего дня, а в архиве — до дня завершения лечения. При переходе на последний день короткого месяца месяц считается полным (31 января → 28 февраля = 1 месяц). Без даты срок не вычисляется.

После сохранения редактор заменяется карточкой, а стрелка «Назад» в карточке открывает список активных или архивных пациентов. При ошибке записи редактор сохраняет введённые значения и показывает сообщение для повторной попытки.

Напоминания о приёмах и возвратах остаются в основных группах. Профгигиена находится в отдельном свёрнутом разделе со счётчиком; его можно раскрыть. Сверху расположены вкладки клиник со счётчиками, включая профгигиену; они переключают отображаемые напоминания. Первой выбирается активная клиника из списка пациентов. Переключение вкладки влияет только на экран напоминаний. Вкладки доступны также для клиник без напоминаний — для них показано пустое состояние. Внутри выбранной клиники остаются группы по срокам и отдельный свёрнутый раздел профгигиены. Вкладки можно переключать стрелками влево/вправо, Home и End.

## Формат данных

Версия локальных данных и JSON-копий — 8. В пациенте добавлено необязательное поле `archivedAt` (момент завершения лечения в ISO-формате), в ортодонтической карте — `appliance` и `bracesInstalledAt` (календарная дата `YYYY-MM-DD`). Поля этапа лечения и следующего действия удалены из формата; миграция убирает их из старых карт. Остальные данные сохраняются. Копии версий 1–7 мигрируются при загрузке и импорте. Некорректная копия отклоняется до замены данных.

Для проверки: `npm run lint`, `npm run test:run`, `npm run build`. Проверки включают перенос старых копий, архив, разделение напоминаний, границы календарных месяцев, последовательные записи, ошибки базы и переходы после сохранения.
